# SBProxy 版本管理

LuCI 的“版本管理”页面分别管理 SBProxy 插件与 sing-box 核心，不需要刷写固件。
页面显示两者的当前版本、发布版本与升级进度。两者都可以切换到发布页提供的任一版本：
升级、同版本重装或降级（回滚）；核心还可选择稳定版或 Alpha。插件切换版本时保留配置；
已安装中文包时会一起切换到相同版本，不额外安装语言包。
切换版本不要求当前已安装的版本仍在发布页中。

人工修复发布递增 `PKG_VERSION` 的小版本，并把 `PKG_RELEASE` 重置为 1，例如 `1.0.2-r11` 之后的修复发布为 `1.0.3-r1`。自动维护产生的插件包只递增 `PKG_RELEASE`。

插件包来自当前架构的 `apk-packages-arm64` 或 `apk-packages-amd64` 发布。
只接受固定包名、发布 URL、SHA-256、APK 名称/版本/架构均匹配的资产。
安装计划只能包含 `luci-app-sbproxy` 和 `luci-i18n-sbproxy-zh-cn`；依赖不满足时停止，
不会更新核心、系统库或其他软件包。

插件与核心共用一个升级锁和后台任务状态，避免并发安装。插件升级前复制管理脚本到
`/var/run/sbproxy-core-manager/worker`，并通过 procd 启动独立服务及 cgroup，
因此替换自身、重载 rpcd/Dropbear 或浏览器断线不会终止任务。
页面重连后继续查询同一任务，不重复安装。

插件安装前只下载并验证所选版本的插件包（及语言包），备份配置并记录核心校验值及运行实例；
不准备当前版本的恢复包。这些文件只在本次任务中使用，放在内存中的 `/tmp/sbproxy-plugin.*`
（不受 LuCI 安装脚本清理 `/tmp/luci-*` 的影响）；只有可用内存扣除 32 MiB 余量后放不下时才改用
`/etc/sbproxy/core/.work.*`。闪存只需容纳新包的安装大小（APK 元数据中的 `installed-size`）
再加 2 MiB 余量，任务结束后临时文件全部删除。
安装后检查包版本、核心校验值、运行服务和管理接口；失败时恢复配置并重启服务，
但不回滚软件包，可重试或改装发布页中的其他版本。
新插件依赖更新的核心时，升级会停止并提示先在“版本管理”中单独升级核心。

核心安装前下载所选版本并校验 SHA-256、APK 名称/版本/架构、必需的编译特性，
并用新核心检查当前配置；闪存需容纳约 4 倍软件包大小再加 16 MiB。核心同样不再保留
回滚包，安装或启动失败时报告错误，可改装发布页中的其他版本。

旧版升级器留下的 `/etc/sbproxy/core/rollback.apk`、`rollback.meta`、`plugin-recovery/`
和 `plugin-packages/` 不再使用，会在下次插件或核心升级开始时删除。
1.0.10-r1 及更早版本的升级器仍要求当前版本在发布页中才能准备恢复包；
若当前版本已不在发布页，需先手动安装一次新版本插件。
状态与日志延用 `/var/run/sbproxy-core-manager/` 和 `/var/run/sbproxy/core-manager.log`。
系统重启或后台进程被强制终止后，任务会显示结果未确认，而不是误报成功。
