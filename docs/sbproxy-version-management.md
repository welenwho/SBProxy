# SBProxy 版本管理

LuCI 的“版本管理”页面分别管理 SBProxy 插件与 sing-box 核心，不需要刷写固件。
页面显示两者的当前版本、发布版本与升级进度；核心支持稳定版、Alpha 和手动回滚。
插件支持升级和同版本重装，保留配置；已安装中文包时会一起升级到相同版本，不额外安装语言包。

插件包来自当前架构的 `apk-packages-arm64` 或 `apk-packages-amd64` 发布。
只接受固定包名、发布 URL、SHA-256、APK 名称/版本/架构均匹配的资产。
安装计划只能包含 `luci-app-sbproxy` 和 `luci-i18n-sbproxy-zh-cn`；依赖不满足时停止，
不会更新核心、系统库或其他软件包。

插件与核心共用一个升级锁和后台任务状态，避免并发安装。插件升级前复制管理脚本到
`/var/run/sbproxy-core-manager/worker`，并通过 procd 启动独立服务及 cgroup，
因此替换自身、重载 rpcd/Dropbear 或浏览器断线不会终止任务。
页面重连后继续查询同一任务，不重复安装。

安装前下载并验证当前插件及语言包的恢复包，备份配置到
`/etc/sbproxy/core/plugin-recovery/`，记录核心校验值及运行实例。
已通过发布来源、SHA-256 与 APK 元数据校验的插件和语言包，会在安装前缓存到
`/etc/sbproxy/core/plugin-packages/`。后续升级可用缓存中的当前版本准备恢复包，
不受发布页仅保留最近三个版本的限制；每次使用缓存都会重新校验 SHA-256、包名、
精确版本和架构。升级成功后仅保留本次目标与上一个版本，缓存仅用于恢复。
固件内置的旧版若既没有缓存、发布仓库也不再保留原包，仍会拒绝安装；需要从原始
构建产物补齐并校验恢复包，避免无法恢复的升级。
升级后检查包版本、核心校验值、运行服务和管理接口；失败时恢复原包及配置。
文件放在持久目录中，避免 LuCI 的安装脚本清理 `/tmp/luci-*` 时删除尚未安装的语言包。

插件回滚仅用于安装失败时自动恢复；核心仍保留历史版本手动回滚。
状态与日志延用 `/var/run/sbproxy-core-manager/` 和 `/var/run/sbproxy/core-manager.log`。
系统重启或后台进程被强制终止后，任务会显示结果未确认，而不是误报成功。
