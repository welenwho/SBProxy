# 智能选节点

在主出口或自定义路由节点中选择 URLTest，再打开「智能选节点」。复用原有的候选节点及订阅选择，不改变分流规则。升级后默认关闭，保留原有选择和自定义检测参数。

普通 URLTest 的新默认值为检测间隔 60 秒、切换容差 75ms。已有显式配置不会被覆盖；清空对应输入框后使用新默认值。默认不中断已有连接，避免切换打断下载和会议；新连接使用新节点。如果需要已有连接立即迁移，可开启「中断已有连接」，连接会重建。

## 检测与切换

- 智能模式使用独立的约 60 秒周期，通过 Google、Cloudflare、Apple 的 HTTPS 小页面测量请求延迟及成功率，结合近期平滑延迟、失败比例、跨目标差异及时间波动评分。
- 每轮检测当前节点、正在竞争的节点和最多四个轮换候选。大量节点逐批探索，避免同时发起大量连接。检测按组串行执行，实际周期至少为本轮所需时间；全失败时会尽早在下一轮复查，不等待完整 60 秒。
- 每轮至少两个目标成功才视为健康。当前节点连续两轮不健康时，可跳过冷却期切换到近期验证健康的备用节点。所有节点失败或控制接口不可用时保留当前选择，不以未经检测的节点作为修复措施。
- 轻量探测通过不能证明节点能完成业务会话。后台读取 sing-box 客户端日志里带入站的真实连接，把 `context deadline exceeded`、`i/o timeout`、连接超时和握手超时记到对应出站。同一轮里出现这类失败记一次；连续两轮出现时，按探测失败的路径切走，不必等探测失败。探测请求和带宽探测不计入。下一轮没有新的真实失败时清零。日志被截断后从新文件继续读。
- 正常切换要求候选的综合分数连续三轮优于当前至少 25%，且分差至少 75，并距离上次自动切换至少 180 秒。延迟记录超过 180 秒不参与选优。
- 开启「检测下载表现」后，每组每 30 分钟最多为三个节点各下载至多 4 MiB，单次最多 8 秒：健康的当前节点、此前测速后综合分最好的备选，以及最久未测速的近期健康节点（从未测速的优先）。仅凭延迟就已输给已知最佳综合分的节点不参与测速。速度只按首字节之后的传输时间计算，不含建连、TLS 握手和首包等待；超时时若已收到至少 64 KiB，按已收到的部分计算。使用独立的本机探测出口，不改变承载用户流量的选择器。
- 评分加上按实测速度估算的下载 1 MiB 所需毫秒数，最多 8000。例如 2 MiB/s 加 500，20 MiB/s 加 50，因此速度相差明显时，延迟高几百毫秒的快节点也能胜出。新结果与 60 分钟内的上一次成功结果按下载耗时平均，减少单次波动。
- 下载检测默认随智能模式启用，可以单独关闭。每组每天最多约 576 MiB 测试正文流量，另有轻量检测和连接开销；多个组分别计费。测速是数 MiB 文件表现的估计，不能保证持续大文件吞吐或每一个网站的访问速度。
- 下载结果保留 60 分钟。只要有健康节点拥有新鲜、成功的下载结果，就只在这些节点之间选优；未测速的节点没有下载惩罚，不能因此直接胜出，而是排队等待测速。同一轮所有下载都失败时视为测速站点问题，不记录结果，下一轮重试；只有其他节点同轮成功时，下载失败才记入评分。测速失败的节点退出比较，但不会仅凭测速失败判定整个节点不可用，也不会把程序锁在当前节点。

## 运行方式

生成原有路由标签下的 selector，并保留一个 URLTest 子组作为初始备用。由 procd 管理 `smart-selection` 后台实例，核心尚未就绪时自动重试。后台通过仅监听 127.0.0.1 的控制接口检测并选择节点；下载探测也只监听本机随机端口。关闭智能模式并保存应用后，恢复普通 URLTest，移除专用探测监听及后台实例。

运行计划和最近评分位于 `/var/run/sbproxy/sing-box-c.json.smart.json` 及同路径的 `.status` 文件；它们只存在于运行目录，不持续写入闪存。重启后重新学习，初始使用 URLTest 子组。后台若异常退出由 procd 重启；此前已选择的节点保持，直至后台重新评估。

## 验证

在带 ubus、uci、ucode 的临时 OpenWrt 环境中运行：

```sh
sh luci-app-sbproxy/tests/router-smart-selection.sh
sh luci-app-sbproxy/tests/test-smart-daemon.sh
ucode -L "$PWD/luci-app-sbproxy/root/etc/sbproxy/scripts" luci-app-sbproxy/tests/smart-score.uc
```

设置 `SING_BOX` 为实际核心路径时，第一个测试还会执行核心配置检查；也可运行 `sh luci-app-sbproxy/tests/test-smart-core.sh`，用实际核心和本机 HTTP 服务验证检测 API、切换 API 与独立探测代理。评分测试覆盖连续失败、正常切换确认、冷却、过期数据、无可用节点、吞吐权重、测速平均及测速候选；后台测试模拟检测 API、部分下载结果和 sing-box 会话日志，验证实际切换请求、会话失败计数及 API 断开时不切换。
