# 智能选节点

在主出口或自定义路由节点中选择 URLTest，再打开「智能选节点」。复用原有的候选节点及订阅选择，不改变分流规则。升级后默认关闭，保留原有选择和自定义检测参数。

普通 URLTest 的新默认值为检测间隔 60 秒、切换容差 75ms。已有显式配置不会被覆盖；清空对应输入框后使用新默认值。默认不中断已有连接，避免切换打断下载和会议；新连接使用新节点。如果需要已有连接立即迁移，可开启「中断已有连接」，连接会重建。

## 检测与切换

- 智能模式使用独立的约 60 秒周期，通过 Google、Cloudflare、Apple 的 HTTPS 小页面测量请求延迟及成功率，结合近期平滑延迟、失败比例、跨目标差异及时间波动评分。
- 每轮检测当前节点、正在竞争的节点和最多四个轮换候选。大量节点逐批探索，避免同时发起大量连接。检测按组串行执行，实际周期至少为本轮所需时间；全失败时会尽早在下一轮复查，不等待完整 60 秒。
- 每轮至少两个目标成功才视为健康。当前节点连续两轮不健康时，可跳过冷却期切换到近期验证健康的备用节点。所有节点失败或控制接口不可用时保留当前选择，不以未经检测的节点作为修复措施。
- 正常切换要求候选的综合分数连续三轮优于当前至少 25%，且分差至少 75，并距离上次自动切换至少 180 秒。延迟记录超过 180 秒不参与选优。
- 开启「检测下载表现」后，每组每 10 分钟为排名靠前的最多三个节点（包括健康的当前节点）各下载至多 256 KiB，单次最多 6 秒，下载耗时计入评分。使用独立的本机探测出口，不改变承载用户流量的选择器。
- 下载检测默认随智能模式启用，可以单独关闭。每组每天最多约 108 MiB 测试正文流量，另有轻量检测和连接开销；多个组分别计费。测速是短文件表现的估计，不能保证持续大文件吞吐或每一个网站的访问速度。
- 下载结果最多保留 20 分钟。优先比较有新鲜下载结果的健康候选；其余候选继续参与轻量轮询和后续下载检测。测速失败降低评分，但不会仅凭测速失败判定整个节点不可用。

## 运行方式

生成原有路由标签下的 selector，并保留一个 URLTest 子组作为初始备用。由 procd 管理 `smart-selection` 后台实例，核心尚未就绪时自动重试。后台通过仅监听 127.0.0.1 的控制接口检测并选择节点；下载探测也只监听本机随机端口。关闭智能模式并保存应用后，恢复普通 URLTest，移除专用探测监听及后台实例。

运行计划和最近评分位于 `/var/run/sbproxy/sing-box-c.json.smart.json` 及同路径的 `.status` 文件；它们只存在于运行目录，不持续写入闪存。重启后重新学习，初始使用 URLTest 子组。后台若异常退出由 procd 重启；此前已选择的节点保持，直至后台重新评估。

## 验证

在带 ubus、uci、ucode 的临时 OpenWrt 环境中运行：

```sh
sh luci-app-sbproxy/tests/router-smart-selection.sh
sh luci-app-sbproxy/tests/test-smart-daemon.sh
```

设置 `SING_BOX` 为实际核心路径时，第一个测试还会执行核心配置检查；也可运行 `sh luci-app-sbproxy/tests/test-smart-core.sh`，用实际核心和本机 HTTP 服务验证检测 API、切换 API 与独立探测代理。评分测试覆盖连续失败、正常切换确认、冷却、过期数据、无可用节点及吞吐权重；后台测试模拟检测 API 和下载结果，验证实际切换请求及 API 断开时不切换。
